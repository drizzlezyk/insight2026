读法：百分比基数为 openclaw/openclaw 全部 issue 63,057 条（open + closed，2026-11-06 快照）。同一 issue 可同时携带多个标签，因此各行百分比之和大于 100%。PR 相关标签作用于 pull request，不进入 issue 统计，故为 0；这与 PPT 中「自动修复 / 自动合并已退役」的说明一致。初筛标签为临时性（preliminary），完整审查后会被移除，因此存量很低。

「需人参与」判定口径：依据标签的官方 description（GitHub Labels API 实取）+ docs/work-lane.md。29 个标签中 11 个需要人参与——其中提交者侧 3 个（intake:needs-repro、intake:needs-environment、needs-info），维护者 / 产品 / 安全侧 6 个（needs-maintainer-review、needs-product-decision、needs-security-review、human-review、manual-only、merge-ready），人工验证 1 个（needs-live-repro），运维干预 1 个（clawsweeper-recovery-stuck，该标签无官方说明，据语义推断）。其余为机器自动分流的纯路由状态。

关键观察：深度分诊标签占绝对主导——no-new-fix-pr（24.70%）、source-repro（19.96%）两行占比合计 44.65%，但标签可重叠，不能当作去重覆盖率；而最终可进入修复队列的 queueable-fix 仅 4.85%，真正「当前 main 高可信可复现」的 current-main-repro 只有 0.18%（113 条）。这印证了 ClawSweeper「大量分流、极少派单」的保守设计。

为什么没有标签？

常见情况证据类型说明
Issue 已关闭 可量化 无标签集合里有 40,308 个 closed issue，占无标签集合 99.2%。源码只对 open issue 同步 advisory labels；关闭项不再获得新的 ClawSweeper 建议标签。
还没有当前、完整的审查报告 机制解释 标签发布要求 issue 为 open，且报告完整、对应当前来源。未进入队列、被维护者请求门禁挂起、预算 / backpressure 暂缓，以及失败或过期的报告，都可能尚不满足发布条件。
完整审查没有命中某个标签条件 机制解释 29 个标签不是“审过就必须任选其一”。例如复现标签依赖复现状态与置信度；needs-info 也只在信息不足的条件满足时投影。没有匹配的建议状态，可以没有 ClawSweeper 标签。
报告提出关闭建议 机制解释 Apply 的 close proposal 路径不会先写 Issue advisory labels，以免标签写入改变更新时间、干扰关闭资格检查。

重要边界：GitHub Search API 只能告诉我们“当前是否带这些标签”，不能逐条判定没标签的原因。因此只有 closed/open 的计数是直接统计；其它原因是依据发布门禁与标签选择源码归纳，不能当作 40,635 条 Issue 的原因分布。没有标签 ≠ 一定没被审查。

接入前后：30–36 天观察窗口的累计闭合比例

OpenClaw 目标仓首次加入 ClawSweeper 事件 dispatcher 的提交是 2026-04-28。据此选取接入前和接入后的两个 7 天创建 cohort；统计各 cohort 中，当前仍 closed 且 closed 日期落在创建周起始日至 cohort 结束后 30 天窗口内的 Issue。每条 Issue 因创建日不同，约有 30–36 天的观察时间。

前后差 创建量下降 46.6% — +45.22 个百分点 37.05% → 82.27%；只表示两段时间的全社区观测差异。

这不是“ClawSweeper 带来 45.22 个百分点提升”的因果结论。它是接入前后全社区 Issue cohort 的描述性变化。两个 cohort 创建量相差 46.6%，Issue 类型与社区流量可能不同；同期还存在 stale、duplicate 等其它自动化。且事件被 dispatcher 投递，不代表每条都实际完成审查。要估计净提升，需要以“实际完成 ClawSweeper 审查”为处理组，匹配同期相似的未处理 Issue / 对照仓库，并校正类型、优先级、创建时间、关闭原因和 reopen。

当前能支持的判断：接入后的样本周，截至约 30–36 天观察窗口结束时的累计闭合比例明显更高（82.27% vs 37.05%）；但由于 cohort 量级和构成变化大，现有公开数据只能说明相关性，不能回答“其中多少由 ClawSweeper 单独造成”。公开数据也没有全社区首次响应 p50/p90、Issue 创建到关闭 p50/p90；前文 39 分 36 秒只代表 ClawSweeper 记录中的创建到最近审查时间。
