02 · 全流程

从事件到关闭：九个节点，两条出口

主链是「摄入 → 只读评审 → 判定 → 发布 → Apply → 安全门 → 关闭」。判定不通过、或任一安全门失败，都走右侧的「保持开放」，并把原因写进 action ledger。

  • 只读判断（Codex）
  • 关键判定
  • 终局 / 安全出口
  • 确定性执行

每个步骤节点都可点击，跳到固定基线 d6179da 的源码行；主链之外还有两条出口：判定不成立（「否」）与安全门失败（「任一失败」）。误关后的人工恢复见 §06。

04 · 判定标准

「已在 main 实现」要有三段证据

不是一句「看起来修了」。关闭策略要求同时给出：当前 main 的源码、修复提交、发布时间或 main-only 时间。缺任何一段，评审必须保持开放；宿主 schema 也会拒绝。

证据项具体要求缺失时
源码等价evidence[] 至少一条同时带 file 与 sha；行为在 current main 的源码（必要时测试/文档）中成立。不能提议关闭
修复提交fixedSha 必填。implemented_on_main requires fixedSha
修复时间 / 版本fixedRelease 或 ISO 时间 fixedAt，至少一个；main-only 也允许，但必须由 fixedAt 或 release 证据支撑。requires fixedRelease or fixedAt
修复 PR（可选）若填 fixedPullRequest：confidence 必须 high、同仓库、已合并、来源在 GitHub 验证白名单内、URL 与编号一致、不能是正在关闭的这条 PR。拒绝关闭
PR 关闭（kind=PR）恰好 1 个同仓库 linked issue；该 PR 当前的 GitHub closingIssuesReferences 仍包含这个仍开放的 issue。泛化的 cross-reference（如 Related to #123）不算。两者都保持开放，且不关 linked issue

issue 与 PR 的硬门不一样。issue 的 implemented_on_main 只需源码 + 提交 + 时间/版本证据，不要求存在一个正式 Fixes 链接。样本 #197766 的 fixing PR 正文只写 Related: #169118，GraphQL 的 closingIssuesReferences 为空，issue 仍按源码等价关闭。PR 则相反：代码相似、功能重叠、main 上有相关 commit 都不够，必须有一个 GitHub 正式关联、同仓库、已合并的 fixing PR。

策略原文（节选）

implemented_on_main: current main fixes the request well enough, even without the proposed workflow, file split, or names; main-only counts. Verify the behavior in source (and tests/docs), then trace the fix from a merged closingPullRequests or referencingMergedPullRequests entry to its commit, timestamp, and first release (git tag --contains <sha>, the changelog, gh api repos/<owner>/<repo>/releases) or current-main-only status. Evidence: source entries with file and sha, a git blame/log/show provenance entry, and that release check; without fixedSha and fixedRelease or fixedAt backed by it, keep open, and invent no release facts.

prompts/review-close-reasons.md · implemented_on_main 条目

「main-only counts」是这条原因最容易被误读的地方：修复还没进 stable 也可以关，但必须有可核验的 fixedAt 或 release 证据；模型不能编造版本号。样本 #198628 的评论同时给出了 merged commit、first batching release 与 stable tag 的 commit，属于证据最完整的一类。

05 · Apply 安全门

评论说 “Proposal only”，关闭在另一层发生

Apply 只从报告里的 typed review_record 读 decision，不从评论散文里猜。读不出 record 就要求一次新评审（skipped_changed_since_review）。下面是四组重检，按执行顺序排列。

GATE 01

决策与证据

  • 关闭原因在本次 apply 的启用集合内；仓库 profile 允许。
  • review_record 可读；decision=close、confidence=high。
  • evidence 含 file+sha；fixedSha；fixedRelease 或 fixedAt。
  • PR：GitHub 验证的、已合并的同仓库 fixing PR 仍然成立。

失败 → skipped_invalid_decision / kept_open

GATE 02

实时状态

  • item 仍 open；updated_at 与 review 快照一致。
  • issue 的 implemented_on_main 必须有当前且精确的 durable review comment。
  • review 后没有新的人类评论；snapshot hash 未漂移。
  • 锁在最后一次读取时检查，尽量缩短关闭前窗口。

失败 → skipped_changed_since_review / skipped_locked_conversation

GATE 03

保护与授权

  • 10 个 close-protected 标签；security 类永不被本原因豁免。
  • 维护者作者 / maintainer 标签：只有 implemented_on_main（和 oversized PR）例外。
  • 产品决策类原因（unsponsored_feature_request 等）永不由 apply 执行。
  • same-author issue/PR 配对仍开放时跳过。

失败 → skipped_protected_label / kept_open

GATE 04

配对与幂等

  • 同作者配对：另一侧仍 open 则不关。
  • 仍有 open closing PR 时不关。
  • PR 配对 issue：独立 review + 独立 durable comment + 当前 closingIssuesReferences 关系。
  • mutation lease、close 配额、idempotencyIdentity 去重。

失败 → skipped_same_author_pair / skipped_open_closing_pr

关闭保护标签（本原因只豁免其中 1 个）

  • maintainer
  • security
  • beta-blocker
  • release-blocker
  • area: security
  • impact:security
  • security-review-required
  • security-sensitive-changed
  • merge-risk: 🚨 security-boundary
  • clawsweeper:needs-security-review

implemented_on_main 的唯一标签例外是 maintainer；这也不豁免 security、manual hold、lock、未决的人类判断、新鲜度或任何实现证据。源码：src/clawsweeper-item-policy.ts:117-131 · src/repair/exact-review-guard-labels.ts:18-35 · 文档：docs/implemented-on-main-close-policy.md

它不是远端事务。GitHub 可以在最后一次读取之后变化，配对关闭的两次 mutation 也可能独立失败。实现上把「issue 记录先归档、父 PR 后关闭」固定下来，并用独立 lease 保护配对 issue；但代码文档明确不承诺跨两个 item 的原子性。docs/implemented-on-main-close-policy.md

06 · 产物与边界

关闭时到底写了什么，什么情况下不写

评论的固定骨架

  1. 固定开场：Thanks for the context here. I did a careful shell check against current main, and this is already implemented.
  2. 一句 verdict / rationale。
  3. 若有高置信度 fixing PR：I found the merged PR that appears to have closed this: [#N: title](url).
  4. 可选的 root-cause cluster / canonical / duplicate 路径。
  5. <details> 折叠区：best solution、两个 review questions、security review、AGENTS.md、最多 6 条 “What I checked”、related people、Codex notes。
  6. 固定收尾：So I’m closing this as already implemented rather than keeping a duplicate issue open.，后接 version marker 与 item marker。

src/clawsweeper-report-comment-helpers.ts:394-395, 437-438, 573-660

标签：关闭原因不写标签

  • P2 / impact:* 等是评审的路由标签，不是关闭原因。
  • implemented_on_main 不产生任何专属标签；原因写在报告 front matter 的 close_reason 与 typed review_record 里。
  • GitHub 侧唯一的机器信号是 state_reason: completed（实现类原因）；其他原因写 not_planned。
  • 生态里看到的 close:already-fixed 来自另一个 bot（claw-marshal）；linked-pr-open 可以同时存在，但它不是关闭原因标签。

src/clawsweeper-close-reasons.ts:25-30 · src/clawsweeper-report-actions.ts:26-53

哪些情况会保持开放

触发条件结果 / 记录
review 后 issue 被编辑、被评论，或 snapshot 变化skipped_changed_since_review；等重审或下轮
review 后维护者锁了对话skipped_locked_conversation；最后读锁，避免竞态

一个需要知道的边界：@clawsweeper stop 不直接等于「阻止本原因关闭」。它做的是加 clawsweeper:human-review、移除 automerge/autofix/merge-ready，然后回复。但 human-review 不在 close-protected 集合里，PR auto-close-exempt 也只覆盖另外几种 PR 原因；按当前公开代码，它本身不会阻断 issue 的 implemented_on_main。它可能因为进入 source_content_revision 哈希而触发一次 fresh review，但这条间接效果未在真实 issue 上验证。src/repair/comment-router.ts:639-656 · src/clawsweeper-apply-guard-activity.ts:192-215

误关之后怎么恢复：人工重新打开 issue 后，已归档的报告会回到 items/ 作为 stale 重新进入审查；编辑正文或评论会形成新的审查意图。ClawSweeper 不会因为一句评论就自动重新打开 issue——恢复动作仍然由人或新一轮评审完成。README.md:116-118, 340-343

07 · 可复用的设计

五条能迁移到其他仓库的规则

1 · AI 只提议，写操作在确定性层

评审模型不持有写权限；关闭、标签、评论都由 Apply 执行。这样即使模型判断错了，也还有一层可审计的拒绝。

2 · 证据是 schema，不是散文

fixedSha、fixedRelease/fixedAt、file+sha 的 evidence 都是字段；缺字段直接拒绝，不靠“评论里看起来提到了”。

3 · 在 mutation 边界重读

评审时的状态不算数。Apply 重新读 issue、标签、锁、配对关系；锁放在最后读，尽量缩短竞态窗口。

4 · 例外必须窄且可命名

只有 implemented_on_main 能绕过 maintainer 身份 / maintainer 标签；security 永远不绕过。例外是一个具名原因，不是“维护者可以特批”。

5 · 关闭原因不要伪装成标签

标签是路由，不是审计记录。要知道为什么关，读持久评论的固定句式、报告 front matter 与 state_reason；不要去找一个并不存在的 close:* 标签。
