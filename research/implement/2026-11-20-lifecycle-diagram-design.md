# Slide 1 底部生命周期图改版设计

## 意图（Why）

`community-issue-pr-io-issue.pptx` 第一页底部的「issue 生命周期 · 谁在做、多久、在哪分叉」目前只陈述了角色、耗时和分叉，没有回答“所以呢”。听众看完只知道流程长什么样，不知道 OpenClaw 到底做对了什么、我们该学哪一段。

本次改版把重点放在：**bot 在约 10 分钟内，把一条原始 issue 变成一份“可决策包”。**

## 目标（Goals）

1. 标题直接给结论：bot 用 ≈10 分钟产出可决策包。
2. 用一块视觉主面板列出 bot 的三项产出：分流结论、复现 + 五维标签、review 意见 + fixPrompt / 关闭理由。
3. 人的一侧保留但降权：只做 3 个关键动作（定夺 / 开 PR / 合并，99.2% 由人）。
4. 保留分叉：证据足 → 关闭 + 理由（可复活）；证据不足 → 补证据；并说明这也发生在 10 分钟内。
5. 底部给一句可迁移的启示：人拿到的是可决策包，不是原始 issue。

## 非目标（Non-goals）

- 不新增统计口径，不引入新的百分比或时长。
- 不改漏斗、右侧原则、设计实现三栏。
- 不改 slide 2–19。
- 不把“≈10 分钟”写成因果结论；它只描述 bot 链路的时点。

## 约束（Constraints）

- 画布 13.333 × 7.5 in（1280 × 720 等比）。
- 字体：微软雅黑；沿用现有色板：ink `16191E`、teal `0F766E`、amber `B45309`、gray `9AA1AC`、border `C9D0D6`。
- 底部区域可用高度约 1.9 in；正文最小 7.5 pt，仅辅助说明可用。
- 只做 python-pptx 手术式修改；其余页的文本与媒体哈希必须不变。

## 方案（Approaches）

- **A. 双段面板 + 时间轴（采纳）**：保留 6 节点时间轴；前 3 节点上方加青色 `bot · ≈10 分钟` 面板，内含三项产出的三列；后 3 节点上方加琥珀色 `人接手 · 小时–天` 面板。底部两条：分叉结果 + 启示。
- B. 产物交接链：只画标签 → 证据 → decision → fixPrompt，丢掉时间轴。洞察更工程化，但失去“10 分钟”的冲击力，未采纳。
- C. 最小改动：只换标题和底部注脚。最省事，但“只是陈述”的观感仍在，未采纳。

## 文案（逐字）

- 标题：`bot 用 ≈10 分钟，把原始 issue 变成「可决策包」`
- 日期：`2026-09-11 → 11-11`
- bot 面板头：`bot · ≈10 分钟`
- bot 面板注：`（~3min / ~9min 为创建后时点）`
- 三列：
  - `① 分流` / `类别 / 缺什么证据`
  - `② 复现 + 标签` / `源码级结论 / 五维标签`
  - `③ review 意见` / `证据链 / fixPrompt / 关闭理由`
- 人面板头：`人接手 · 小时–天`
- 人面板注：`只做 3 个关键动作`
- 人面板行：`定夺（修 / 挂起 / 路由）· 开 PR · 合并 99.2% 由人`
- 分叉行：`分叉也在 10 分钟内：证据足 → 关闭 + 理由（可复活）｜证据不足 → 补证据`
- 启示行：`启示：人拿到的是「可决策包」，不是原始 issue —— 省下的是判断前的整理时间。`
