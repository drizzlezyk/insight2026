ClawSweeper：把 issue / PR 积压变成「可关闭建议」的保守型审查机器人

它是 OpenClaw 仓库群里的自主维护者——周期性扫遍所有开放的 issue 与 PR，写出带证据的审查报告，并只对未变更、高置信、策略允许的项执行关闭。核心立场是「算力充裕，信任稀缺」：判断交给模型，代码只守护信任边界。

定位

它是什么，不是什么

一句话：扫描所有 issue 与 PR，给出「哪些可以关闭、为什么」的建议，并只在确定性安全门通过后执行关闭。

  • 服务于：OpenClaw 维护者优先、贡献者次之——让每位贡献者更快拿到一份诚实、实质的审查。
  • 生产目标仓库：openclaw/openclaw、openclaw/clawhub、openclaw/clawsweeper、openclaw/fs-safe；其他 openclaw/* 与 steipete/* 可通过配置档或保守的通用回退接入。
  • 非通用自动关闭机器人：审查只做「提议」，执行有护栏；审查阶段 Codex 拿不到写权限，每次 GitHub 变更前都要用实时状态再校验一遍。
  • 对外边界：OpenClaw 托管的实例不是公共审查服务，不为第三方仓库免费审查——自用请 fork 并自建部署。

架构

两条运行通道

Review Lane · 只提议

审查通道

  • 定时 + 事件驱动的 issue/PR 审查
  • 每项产出耐久报告
  • 同步公共审查评论
  • 永不关闭任何条目

Apply Lane · 受护栏约束

执行通道

  • 受护栏约束的关闭 / 评论变更
  • 审计、对账、状态发布
  • 执行前重取实时状态校验
  • 每 15 分钟唤醒，无事即退

Issue 与 PR 的治理流程

能力清单

能力说明
审查与评论
定时 + 精确事件审查调度任务扫开放 issue/PR；目标仓库可通过无密钥 OIDC Worker 转发精确事件，实现低延迟的单条审查。
耐久报告每次审查写出 records/<repo>/items/<number>.md，含判定、证据、拟发布评论、运行元数据与 GitHub 快照哈希。
原地评论同步每项仅维护一条带标记的公共评论并原地编辑，避免重复刷屏；临时租约评论在发布后清除。
关联上下文审查提示注入关联 issue/PR、关闭式链接、本地历史报告、可选的 gitcrawl 聚类与实时 issue 搜索，用于判重/取代。
根因评估持久化一个「仅提议」的类型化根因判断（同仓库 URL、至多一个证据支撑的规范项），不做修复、不做抑制。
建议性标签把结构化结论投影为 GitHub 标签（当前 main 复现、源码级复现、关联开放 PR、可排队修复、适合 good first issue、缺信息等），仅供筛选。
执行与状态
带护栏的关闭执行前重新拉取实时状态，校验标签、维护者署名、issue/PR 配对状态、快照漂移与仓库配置档规则。
决策包（Decision Packet）对需要维护者裁决的报告，Codex 输出结构化 JSON（问题、理由、选项、建议、可能负责人），由确定性代码校验并落盘。
多层存储规范记录存 Cloudflare Durable Object 并快照至 R2；不可变 ledger/v1/ 行动账本、素材、重试缓存均在 R2；运行态留在 clawsweeper-state 仓库。
命令与集成
维护者命令路由响应 @clawsweeper 系列评论命令，校验仓库权限与当前源评论后再受理。
GitHub App Webhook可选 App 在 Actions 回退启动前，即耐久记录并确认合格的审查评论版本；精确任务被 Worker 合并与租约化。
本地分支审查可审查本地分支范围，仓库与 GitHub 访问保留在本地，Codex 仅连接配置的模型服务（pnpm local-review）。
超大 PR 关闭通道对改动超过 50,000 行的 PR，在水合/扫描/模型审查之前就提议关闭（维护者可用 size: accepted-large 豁免）。

调度

扫描节奏：越新越勤

  • 热/新条目：每小时检查一次，最新队列边缘有 5 分钟的接入节奏。
  • 30 天以内的 PR / issue：离开热窗口后每日检查一次。
  • 更老的静默 issue：每周检查一次。
  • 执行通道：每 15 分钟唤醒一次，没有「未变更的高置信关闭提案」就快速退出。

安全边界

只在「明显属于下列情形」时才提议关闭

可提议关闭的 10 类情况

  • 在当前 main 已实现
  • 在当前 main 无法复现
  • 更适合放进 ClawHub skill/plugin，而非核心
  • 重复或被取代（有规范项）
  • 低信号 PR：分支与主题基本无关或不可合并
  • 外部低评分 PR：迟迟拿不出真实行为证明、闲置 14 天以上
  • 外部 PR：草稿/等待作者/检查失败，废弃 30 天以上
  • 具体但在本源仓库中无法行动
  • 前后不一致，无法采取任何行动
  • 超过 60 天、数据太少难以验证的陈旧 issue

默认保持开放的保护规则

  • 维护者署名的条目保持开放（除非能验证已在 main 实现）。
  • 被 Fixes #123 等关闭式语法引用的 issue，在该 PR 合并/关闭前保持开放。
  • 同一作者的 issue/PR 配对一起保持开放，除非已解决或维护者明确要求关一侧。
  • PR 判重/取代需要安全规范目标：目标为已关闭未合并、缺证明、F 评级、已被提议关闭、不可干净合并的一律不关。
  • ClawHub 与 ClawSweeper 自审更严格：仅当 main 已实现且有源码证据时才可关闭 PR。

设计立场

为什么这样设计

算力充裕，信任稀缺。 模型调用越来越便宜，而工程时间与信任不是。凡是能用「明确提示 + 可审计输出」的模型判断替代的，就优先用模型；代码只存在于信任边界上：鉴权、幂等、只增行动账本、花费上限、破坏性动作闸门。

质量底线

  • 每个动作都带一条维护者可读的理由。
  • 错误关闭必须能一条评论内复活。
  • 系统自身的失败要先被系统分诊，再让人看到。

非目标

  • 追求完美确定性（用验证换正确性，而非僵化）。
  • 零成本运行。
  • 在产品方向上取代维护者的品味。
