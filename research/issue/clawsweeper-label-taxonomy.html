00 · 全景 九个维度，issue 与 PR 各占一半

ClawSweeper 的标签体系分成三大块：issue 侧（评级 / 复现证据 / 路由 / 优先级 / 影响 / 成熟度 / 特殊标签）、PR 侧（评级 / 合并风险 / 证明 / 状态）、以及横跨两者的治理保护标签。唯一「两者都贴」的普通维度是优先级 P0–P3；影响与成熟度只贴 issue，合并风险、证明、PR 评级与 PR 状态只贴 PR。

02 · 复现证据 clawsweeper:* 证据标签（5 个，issue 专用）

09 · 治理 / 保护 关闭保护、自动关闭豁免、自动化控制

这些不是「贴上去的洞察」，而是门禁——阻止 ClawSweeper 自动关闭或自动合并某条 item。全部定义在 src/repair/exact-review-guard-labels.ts。作用域跨 issue 与 PR。

09a · 关闭保护 CLOSE_PROTECTED_LABEL_NAMES（10 个）

只要 item 上出现下面任一标签，ClawSweeper 就不允许自动关闭它——安全、发布阻断、维护者标记等。

security · beta-blocker · release-blocker · maintainer · area: security · impact:security · security-review-required · security-sensitive-changed · merge-risk: 🚨 security-boundary · clawsweeper:needs-security-review

在关闭保护基础上，再追加一批阻止自动合并的标签。

这些标签意味着「这条 PR 由人 / 特定自动化模式在管」，不能自动关闭。

结论 三层结构：评级是派生，路由是决策，治理是门禁

1 · 评级标签是派生结果

issue-rating 与证据标签不是模型直接填的，而是「复现状态 × 置信度」查表映射的产物。想理解它，得回到 schema 里那两个原始字段。

2 · issue 与 PR 是两套平行体系

同名动物标签在 issue 上判「quality」、在 PR 上判「readiness」。影响 / 成熟度只贴 issue，合并风险 / 证明 / PR 状态只贴 PR，只有 P0–P3 两边都贴。

3 · 治理标签不是洞察，是门禁

security、clawsweeper:human-review 这类标签不描述 item，而是阻止 ClawSweeper 自动关闭或合并——是安全阀，不是评分。
