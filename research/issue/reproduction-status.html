「可复现」维度：ClawSweeper 怎么判断一条 issue 是哪种

动物评级只是表层。真正的判断发生在更早一步：模型先给每条 issue 判一个 reproductionStatus（可复现状态，5 选 1）加一个 reproductionConfidence（置信度，3 选 1），代码再把这对组合查表映射成动物标签和证据标签。这份报告拆开这一步——这个维度有几种值、书面判据到底写了多少、模型凭什么选。

01  这个维度有几种：一个字段，两层标签

「可复现」在 ClawSweeper 内部是一个字段、5 个取值，向外投影成两种 GitHub 标签：一层是 7 个动物评级（issue-rating:），一层是 5 个证据标签（clawsweeper:*）。真正承载「复现类型」语义的是下面这 5 个值。

reproduced
在 current-main 上真实复现。最高证据——schema 有逐字描述。
描述原话：「high-confidence current-main reproduction」
source_reproducible
源码级可复现：读代码确认 bug 路径可达，但没实际跑出失败。
描述原话：「source shows the path without a failing run」
not_reproduced推断
尝试复现失败，或在 main 上已不复现。schema 未描述。
推断依据：证据标签 not-repro-on-main「no longer reproduces on main」
unclear推断
无法判定：证据不足，说不清能不能复现。
推断依据：证据标签 needs-info「needs more reporter information」
not_applicable推断
不适用：不是可验证的 bug（如 feature request）。
推断依据：动物标签 🌊 off-meta tidepool「does not apply」

这 5 个值又派生出一组证据标签（只在命中条件时打，见 04 矩阵）：clawsweeper:current-main-repro、clawsweeper:source-repro、clawsweeper:not-repro-on-main、clawsweeper:needs-live-repro、clawsweeper:needs-info——所以「这个维度的标签」严格说是 5 个内部值 + 5 个公开证据标签，动物评级是它的下游再投影。

02  书面判据有多薄：只有两句话

这是本报告最关键的发现。模型在判定「这条 issue 属于哪种可复现」时，拿到的书面 rubric 少得惊人：

字段取值schema 里的描述状态
reproductionStatusreproducedhigh-confidence current-main reproduction✅ 有描述
reproductionStatussource_reproduciblesource shows the path without a failing run✅ 有描述
reproductionStatusnot_reproduced—（无任何描述）❌ 靠名字推断
reproductionStatusunclear—（无任何描述）❌ 靠名字推断
reproductionStatusnot_applicable—（无任何描述）❌ 靠名字推断
reproductionConfidencehigh / medium / low—（无任何描述）❌ 无描述
reproductionAssessment（自由文本）Public answer to: Do we have a high-confidence way to reproduce the issue? With the evidence.✅ 有描述

判据不是一份详细 rubric，而是「枚举名 + 两句定义 + 一句必须用证据回答的问题」。schema/clawsweeper-decision.schema.json 里 5 个取值只给前 2 个写了描述（:518–521），reproductionConfidence 三档完全空白（:523–526）。其余三个取值——not_reproduced、unclear、not_applicable——模型只能从名字本身和它派生的证据标签语义去猜。

这意味着 ClawSweeper 把「怎么判复现类型」这件事大部分委托给了模型的深度阅读能力，而不是事先写死逐条判据。prompt 里唯一的总原则是那句反复出现的：review-item.md ——「Review deeply before closing: high confidence means you read enough current code, tests, docs, history…」（高置信 = 你真的读够了代码 / 测试 / 文档 / 历史）。

03  判定流程：模型判枚举，代码选标签

一条 issue 从进来到最后被贴上「🦞 diamond lobster」或「needs-info」，走的是下面这条链。注意职责切分：模型只负责「判」，代码只负责「贴」。

只读
模型进入只读环境：只能用 rg sed nl find git log/show/diff/blame 和 gh api 的 REST GET；不许写任何东西。prompts/review-item.md · Ground rules
深读
对 issue 做深度阅读：代码、测试、文档、历史、评论、关联项，搜同义词和旧名。「高置信 = 读够了」——几个独立证据胜过标题、一次 rg 命中或一个邻近文件。prompts/review-item.md · Review
落答
写出 reproductionAssessment：「Do we have a high-confidence way to reproduce the issue?」 的公开答案，并配 evidence（仓库 / 文件 / 行号 / commit SHA）。这是唯一成文的复现判断。schema :537–540
压枚举
把自由文本判断压缩成两个枚举：reproductionStatus（5 选 1）+ reproductionConfidence（3 选 1）。这一步就是「判它是哪种」的落点。schema :518–526
查表
代码 issueRatingLabelForState() 按首条命中的顺序，把（状态 × 置信度）映射成动物标签，同时 wantedIssueAdvisoryLabels() 派生出证据标签。模型不选标签，模型选枚举，代码选标签。clawsweeper-label-selection.ts :149–204

05  证据标签的逐字原话

5 个 clawsweeper:* 证据标签的 label 描述（GitHub API 逐字，clawsweeper-policy.ts :451–476）：

标签颜色原话（label 描述）
clawsweeper:current-main-repro#0A3069ClawSweeper found a high-confidence current-main issue reproduction.
clawsweeper:source-repro#0A3069ClawSweeper found a high-confidence source-level issue reproduction.
clawsweeper:not-repro-on-main#2DA44EClawSweeper found high-confidence evidence that this issue no longer reproduces on main.
clawsweeper:needs-live-repro#FBCA04ClawSweeper needs live local, crabbox, or manual validation to confirm this issue.
clawsweeper:needs-info#6E7781ClawSweeper needs more reporter information before it can verify this issue.

注意「可复现」不是一个线性的 1–5 分数，而是两条轴：一条是「有没有复现路径」（reproduced → source_reproducible → unclear → not_reproduced），另一条「这问题到底是不是 bug 该被评分」（not_applicable 单独岔出去）。reproductionConfidence 再给前者叠加可信度。

06  判据与输入：模型到底拿到什么

指导「可复现」这个维度的东西分两类：判据 prompt（告诉模型怎么判）和输入上下文（喂给模型什么料）。两者都很薄——判据只有几段文字，输入里关联项的 body 还被剥掉。

一句话：指导这个维度的「判据」= schema 两句话 + 「read enough」总原则 + cannot_reproduce 一段判据；「输入」= issue 全量正文 + 讨论时间线 + 剥了 body 的关联项索引 + 只读源码 checkout + AGENTS.md。模型据此写出带 evidence（repo/file/line/sha）的 reproductionAssessment，再压成 reproductionStatus + reproductionConfidence 两个枚举——不执行代码，只做静态源码判断 + 评估报告者证据。

07  每个标签的比例与 completed 关闭占比

5 个证据标签是互斥的（一条 issue 只有一个 reproductionStatus，至多命中一个证据标签），所以可以直接数占比。窗口 2026-09-13 ~ 11-13，gh search/issues 快照（2026-11-15）。证据标签覆盖了 6,968 / 9,242 ≈ 75% 的已评级 issue；其余 25% 是「不适用」（🌊 tidepool）或落在不打证据标签的档位。

两个结论：① source-repro 占绝对主导（73.8%）——「源码级可复现」是这个维度的默认形态，也解释了 🦞 lobster 为何是最高频评级；而真正的「已复现」current-main-repro 只有 17 条（0.2%），正好印证上一节：既然从不执行代码，绝大多数结论只能停在「源码级」，几乎到不了「真复现」。② completed 关闭占比是一条清晰梯度：source-repro 88.4% → not-repro-on-main 82.8% → needs-live-repro 59.9% → needs-info 45.7%。可复现性越强，越可能被 completed（已解决）关掉；反之 needs-info（信息不足）里超过一半（54.1%）以 not_planned（不修）收场。

结论

01

「可复现」维度是一个字段 5 个值，向外投影成 5 个证据标签 + 7 个动物评级，不是一套并列的独立标签。

02

书面判据薄到只有两句话：reproduced 和 source_reproducible 有描述，其余 3 个值 + 置信度三档全靠模型从名字和「深度阅读」自行推断。

03

判定是模型判枚举、代码选标签的切分：模型读代码/测试/历史后填 reproductionStatus+reproductionConfidence+reproductionAssessment，标签由 issueRatingLabelForState() 首条命中确定，可复现、可审计。
