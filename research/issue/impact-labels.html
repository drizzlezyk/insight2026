影响维度：ClawSweeper 按损害类型给 issue 分类

「优先级」回答「多紧急」，而「影响」回答「伤到的是什么」——数据、安全、崩溃、消息、会话状态、认证、UX。与优先级「单选」不同，影响是多选：一条 issue 最多带 3 个 impact:* 标签。这个维度只作用于 issue，模型填一个 impactLabels 数组，代码按固定顺序贴上去。

03 · 判定流程 多选数组，按固定顺序贴

与优先级的一比一不同，模型填的是数组 impactLabels（最多 3 项）。代码 nextImpactLabels() 先清掉旧 impact 标签，再按 IMPACT_LABELS 的定义顺序遍历，把命中的依次加回去——所以最终标签顺序是固定的（data-loss → security → … → other），不代表模型给的权重。

定影响的核心规则在 review-item.md 第 51 行，与优先级共用一段。关键约束：UX 阻断优先、能用具体标签就别用 other、证据支持到哪就说到哪、每个标签只解释一次。

输入：判断影响看的是 issue 正文描述的用户可感知后果。模型不运行代码，只从「丢了什么、崩了什么、卡住了谁」的文字证据里归类。

结论 影响 = 「伤的是什么」的多选分类

1 · 与优先级正交

优先级问「多急」，影响问「伤哪」。同一条 P2 可能是崩溃循环，也可能是 UX 摩擦。

2 · 多选，最多 3 个

一条 issue 可同时带多个 impact 标签，颜色红橙黄灰四档反映严重度梯度。

3 · 三个红档命运各异

data-loss 几乎必修、security 长期挂起、ux-release-blocker 快速关闭但常是 not_planned。
