优先级维度：ClawSweeper 怎么给 issue 定 P0–P3

优先级是最「扁平」的一个维度：模型只填一个字段 triagePriority，代码一比一把它翻成标签，没有置信度、没有派生矩阵。它也是唯一一个同时贴在 issue 和 PR 上的普通维度。真正的判断难度不在「翻译」，而在模型怎么从影响 / 严重度 / 紧急度里聚合出一个 P 值。

01 · 这个维度有几种 4 个标签 + 1 个「空值」

字段 triagePriority 是 5 选 1：P0–P3 加一个 none。但只有前 4 个会变成标签，none 表示「不贴优先级标签」——所以「有几种」的答案是4 种标签。

作用域：nextPriorityLabels() 在 desiredClawSweeperLabelsFromPublicReport() 里被无条件调用（不进 isPullRequest 分支），所以 P 标签 issue 和 PR 都贴——这是它与「影响 / 成熟度」等 issue 专用维度的关键区别。

02 · 书面判据 schema 一段话，四个值一次说清

优先级是少数几个 schema 里把判据写得比较完整的字段之一（不像路由的 workCandidate 是空的）。逐字如下：

schema/clawsweeper-decision.schema.json · triagePriority
P0: Emergency: data loss, security bypass, crash loop, or unusable core runtime. P1: Urgent regression or broken agent/channel workflow affecting real users now. P2: Normal priority bug or improvement with limited blast radius. P3: Low-risk cleanup, docs, polish, ergonomics, or speculative feature. none: no priority label.

03 · 判定流程 一比一查表，没有置信度

05 · 关键 prompt 与输入

模型怎么定 P 值，靠 prompts/review-item.md 第 51 行。注意它把「UX 阻断」单列成最高优先的覆盖规则——非技术用户被卡在安装/登录/首次可用，直接判 P0。

prompts/review-item.md · Labels, UX override first
Labels, UX override first: a non-technical first-time or community user blocked in website/download/install/update/setup/onboarding/auth/provider setup/first useful run/in-product recovery with no in-product way forward … is P0 plus impact:ux-release-blocker … Recoverable docs/support/guessing paths are P1/P2 plus impact:ux-friction; cosmetic or fully recoverable in-product confusion is P2/P3; advanced or power-user terminal/config workflows are not promoted. Otherwise choose triagePriority from user impact, severity, confidence, and urgency for the whole item, separately from finding priorities and repairability …

输入：定优先级看的是整条 item 的用户影响、严重度、置信度、紧急度；代码提示它要「与 finding 优先级、可修性分开」，且 P0–P2 是必做、P3 只是建议（PR 侧语义）。

一眼结论：P 值呈「中间大两头小」的钟形，P2 占 56%。但 completed 占比并不随优先级单调下降——P1 反而最高（79.6%），P0 只有 58.0%。原因：P0 里有大量「用户以为是紧急事故、实则是误报或不可行」的情况，被快速以 not_planned 关掉；P3 作为低优先级 cleanup/feature，近一半（45.5%）最终被搁置。

结论 优先级 = 一个字段，一比一翻译

1 · 最扁平的维度

没有置信度、没有派生矩阵，triagePriority 5 选 1 直接查表贴标签，none 则不贴。

2 · 唯一 issue+PR 通用

其它普通维度都分 issue / PR，只有 P0–P3 两边都贴，因为「紧急度」是 item 级而非对象级属性。

3 · 聚合判断在模型侧

难点在模型从影响 / 严重度 / 紧急度里定一个 P 值——尤其「UX 阻断强制 P0」这条覆盖规则。
